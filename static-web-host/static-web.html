1. Static Website Kya Hoti Hai?

Static website wo website hoti hai jisme server-side par har request ke liye database ya backend code se page generate karna zaroori nahi hota. Usually ready-made HTML, CSS, JavaScript aur assets directly serve kiye jaate hain.

HTML

Structure aur content.

CSS

Design, layout, colors aur responsive UI.

JavaScript

Browser-side interaction aur logic.

Assets

Images, icons, fonts, PDFs etc.

Real-Life Analogy

Static website ko ek printed brochure ki tarah samjho: content pehle se prepared hai aur server mainly prepared files deliver karta hai.

Browser
→
Web Server/CDN
→
HTML + CSS + JS
→
Rendered Page

Static vs Dynamic

FeatureStaticDynamic
Typical filesHTML/CSS/JS/assetsFrontend + backend + database
Server processingUsually minimal for page generationCommonly required
DatabaseNot required for basic siteOften used
ExamplesPortfolio, docs, landing pageE-commerce, social network, banking app
Important: Static ka matlab “non-interactive” nahi hai. Browser-side JavaScript menus, animations, calculators aur API calls kar sakta hai.

3. GitHub Pages Kya Hai?

GitHub Pages GitHub repositories se static websites publish karne ki hosting service hai. Repository mein website files rakhkar Pages ke through public URL par serve kiya ja sakta hai.

→
Git Repository
→
GitHub Repository

GitHub Pages
→
Website

Important Concepts

  • Repository: Source files and Git history.
  • Branch: Development/source line.
  • Publishing source: Pages settings mein branch/folder selection.
  • index.html: Common entry document.
  • Custom domain: Apna domain configure kar sakte ho.
  • HTTPS: Secure web connection configuration.

6

Stage & Commit

git add .
git status
git commit -m "Initial static website"
7

GitHub Repository Create Karo

  1. GitHub open karo.
  2. New repository select karo.
  3. Name set karo, e.g. my-static-site.
  4. Visibility choose karo.
  5. Existing local project hone par unnecessary auto-created files se initial history conflict avoid kiya ja sakta hai.
  6. Repository create karo.
8

Remote Add Karo

git remote add origin https://github.com/YOUR-USERNAME/my-static-site.git
git remote -v
9

Main Branch & Push

git branch -M main
git push -u origin main

-u upstream tracking set karta hai.

10

GitHub Pages Enable Karo

  1. Repository → Settings.
  2. Pages section open karo.
  3. Publishing source/configuration choose karo.
  4. Branch: main.
  5. Folder: /(root) if files root mein hain.
  6. Save/Apply karo.
11

Deployment Verify Karo

Pages section mein published URL check karo. Website open karke HTML, CSS, JS, images, links, responsiveness aur browser console verify karo.

6. All Important GitHub Static Deployment Concepts

6.1 Local vs Remote Repository

LocalRemote
Aapke computer par Git repositoryGitHub par hosted repository
Local commitsPush kiye commits
DevelopmentCollaboration/deployment source

6.2 Branch

Branch development line hai. Pages configured source branch/folder se website publish kar sakta hai.

6.3 Root Folder vs /docs

Agar publishing source /(root) hai to files selected branch ke root mein expected hoti hain. Kuch configurations mein /docs folder publishing source banaya ja sakta hai.

6.4 Relative Paths

<link rel="stylesheet" href="css/style.css">
<img src="images/logo.png" alt="Logo">

Project-site subpaths ke context mein relative paths often safer hote hain.

6.5 Case Sensitivity

Linux-based hosting par filename case matter kar sakta hai: Profile.jpg aur profile.jpg ko same assume mat karo.

6.6 Repository vs Pages

GitHub RepositoryGitHub Pages
Code/files/history storeStatic website publish
Version control/collaborationWeb hosting/publishing

6.7 GitHub Actions

Advanced workflow mein Actions build, test aur deploy automate kar sakta hai—especially jab source ko build step ki zaroorat ho.

6.8 Static Site Generators

Jekyll historically GitHub Pages ecosystem ka important part raha hai. Simple HTML/CSS/JS site ke liye Jekyll mandatory nahi hai.

6.9 Public/Private & Publishing

Repository visibility aur published website visibility ko separate concepts samjho. Current GitHub account/plan/configuration ke according Pages availability vary kar sakti hai.

Static assets.

What it is NOT

  • Database server.
  • Secure place for frontend API secrets.
  • Every full-stack architecture ka replacement.

9. JavaScript API Calls & Secrets

Static frontend browser se API call kar sakta hai, lekin frontend mein shipped secret secure nahi hota.

fetch("https://api.example.com/data")
  .then(response => response.json())
  .then(data => console.log(data));
Never expose secrets:
const API_KEY = "MY_SECRET_API_KEY";
Browser-delivered values user inspect kar sakta hai. Sensitive credentials backend/secure secret-management architecture mein rakho.

10. Common Errors & Troubleshooting

404 / Page Not Found

  • Pages enabled?
  • Correct branch?
  • Correct folder?
  • index.html correct location?
  • Correct URL?

CSS/JS/Images Missing

  • Path exact match?
  • Filename case correct?
  • File committed/pushed?
  • Browser Network/Console check?

Local Works, GitHub Pages Doesn't

Deployment path, case sensitivity, missing files, asset URLs, branch/source folder aur build configuration investigate karo.

Push Rejected

git pull --rebase origin main
git push

Commands blindly run mat karo; remote/local history aur possible conflicts samjho.

Authentication Error

GitHub HTTPS operations ke liye modern credential/token mechanisms use hote hain; SSH key authentication bhi common hai.

16. Interview Questions

  1. Static website kya hoti hai? Pre-built web files that can be served without per-request server-side page generation.
  2. GitHub Pages kya hai? GitHub repository source se static websites publish karne ki hosting service.
  3. Repository vs Pages? Repository source/version-control location; Pages website publishing mechanism.
  4. index.html important kyun? Common default entry document.
  5. Backend GitHub Pages par run kar sakte hain? Traditional persistent backend runtime iska purpose nahi hai.
  6. Static site mein JavaScript? Yes, browser-side JavaScript use ho sakta hai.
  7. git push? Local commits ko remote repository par send karta hai.
  8. Deployment mein branch ka role? Configured publishing source branch/folder se Pages publish kar sakta hai.
  9. CSS load nahi? Path, case, repository contents, source branch/folder aur browser Network/Console check.
  10. DevOps learning value? Git, remote repo, deployment, automation aur CI/CD fundamentals practice.

17. Common Mistakes

  • Wrong branch/source folder
  • Missing index.html
  • Incorrect CSS/JS/image paths
  • Filename case mismatch
  • Changes commit/push na karna
  • Secrets/API keys public repo/frontend mein rakhna
  • Huge unoptimized assets
  • Sirf localhost test karna

18. Deployment Checklist

  • Website locally working
  • index.html ready
  • CSS/JS/images verified
  • .gitignore configured
  • No secrets committed
  • git status checked
  • Commit created
  • GitHub repository created
  • Remote configured
  • Correct branch pushed
  • GitHub Pages enabled
  • Correct source branch/folder selected
  • Published URL tested
  • Console checked
  • Mobile responsiveness tested
  • Custom domain/DNS checked if applicable

19. One-Minute Revision

Static Website = Mainly pre-built HTML/CSS/JS/assets.

Git = Version control system.

GitHub = Git repositories + collaboration platform.

GitHub Pages = Repository source ko static website ke roop mein publish karne ka hosting mechanism.

Deployment flow = Local Code → Git → Commit → GitHub → Pages → Public URL.

Update flow = Edit → Add → Commit → Push → Pages deployment update.
