Git Diff Command

Complete Beginner → Intermediate study material for understanding, reading and using git diff effectively.

Git git diff Working Tree Staging Area HEAD Commits Code Review DevOps
Core idea: git diff ka main kaam hai Git ke different states ke beech changes ko compare karke dikhana.

1. Git Diff Kya Hai?

git diff Git ka ek comparison command hai. Iska use files/code mein hue changes ko dekhne ke liye kiya jata hai.

Simple language mein:

git diff = “Maine kya change kiya hai?”

Jab aap kisi tracked file ko edit karte ho, Git purane committed/staged version aur current version ke differences ko identify kar sakta hai. git diff un differences ko line-by-line show karta hai.

Real-Life Analogy

Imagine karo aapke paas ek document ka old version hai aur aapne usme kuch lines change kar di. Ab aap compare karna chahte ho ki exactly kya add, delete ya modify hua. Git diff wahi comparison karta hai.

Old Version
↔
Current Version
→
Differences

2. Git ke 3 Important Areas

git diff ko samajhne ke liye Git ke three-state model ko samajhna bahut important hai.

Working Tree

Actual files jinke andar aap currently changes kar rahe ho.

Staging Area

Changes jo next commit ke liye git add se stage kiye gaye hain.

Repository / HEAD

Committed history. HEAD current commit ko refer karta hai.

HEAD / Last Commit
→
Staging Area
→
Working Tree
Most important: Different git diff forms different areas ko compare karte hain. Isi wajah se git diff, git diff --staged aur git diff HEAD ke results different ho sakte hain.

3. Git Diff ka Mental Model

CommandComparisonMeaning
git diff Working Tree ↔ Index/Staging Area Unstaged changes dekho.
git diff --staged Staging Area ↔ HEAD Next commit mein kya jayega, dekho.
git diff HEAD Working Tree ↔ HEAD Last commit ke comparison mein total local changes dekho.
git diff HEAD~1 HEAD Two commits Do commits ke beech difference dekho.
Golden Rule:
git diff → unstaged changes
git diff --staged → staged changes
git diff HEAD → staged + unstaged changes relative to HEAD

4. Basic Syntax

git diff

Specific file ke liye:

git diff filename.txt

Specific directory ke liye:

git diff path/to/directory/

Staged changes:

git diff --staged

Ya:

git diff --cached

HEAD ke against:

git diff HEAD

6. Added vs Deleted Lines

function calculate(a, b) {
-  return a - b;
+  return a + b;
}

Yahaan:

  • - return a - b; → old line removed/replaced.
  • + return a + b; → new line added.
Important: Diff mein + aur - ko blindly “file mein plus/minus” mat samjho. Ye comparison output ke markers hain: new side par added line aur old side par removed line.

7. What is a Hunk?

Diff output mein hunk ek particular area ka change block hota hai.

@@ -10,7 +10,8 @@
 const user = getUser();

 function login() {
-  return false;
+  validateUser(user);
+  return true;
 }

@@ -10,7 +10,8 @@ change ke location aur old/new line ranges ke baare mein information deta hai.

Interview point: Hunk diff ka ek localized block of changes hota hai, jisme surrounding context lines bhi ho sakti hain.

8. git diff vs git diff --staged

Scenario

echo "Line 1" > demo.txt
git add demo.txt

# Ab file ko aur edit karo
echo "Line 2" >> demo.txt

Ab file ke do versions ho sakte hain:

  • Staging area mein: Line 1
  • Working tree mein: Line 1 + Line 2

Normal Diff

git diff

Ye staging ke comparison mein working tree ke unstaged change ko show karega.

Staged Diff

git diff --staged

Ye HEAD ke comparison mein staged change ko show karega.

HEAD
↔
Staged
↔
Working Tree

9. git diff --cached

--cached aur --staged commonly same purpose ke liye use hote hain.

git diff --cached

Ye staged changes ko current HEAD ke comparison mein dikhata hai.

Pre-commit review: git diff --staged ka use karke commit karne se pehle verify karo ki exactly kya commit hone wala hai.

10. git diff HEAD

git diff HEAD

Ye current HEAD aur working tree ke beech overall difference dekhne ke liye useful hai. Isme staged aur unstaged local changes ka combined picture mil sakta hai.

Use case: “Last commit ke baad maine overall kya-kya change kiya hai?” → git diff HEAD

11. Do Commits ke Beech Difference

Specific commits compare karne ke liye:

git diff COMMIT1 COMMIT2

Example:

git diff abc1234 def5678

Recent commits ke beech:

git diff HEAD~1 HEAD

Do commits ke beech changed files ka summary:

git diff --stat HEAD~1 HEAD
Direction matters: git diff A B mein comparison A se B ki taraf interpret kiya jata hai. Order reverse karne par added/deleted perspective reverse ho sakta hai.

12. Commit vs Commit Example

git log --oneline --max-count=4

Suppose:

f5a9c21 Update login
c82b711 Add login
a102f90 Initial commit

First two commits compare:

git diff c82b711 f5a9c21

Last commit ka change:

git diff HEAD~1 HEAD

13. Commit Range: Two Common Forms

Two endpoints compare karna

git diff A B

Ye A aur B ke resulting trees ka difference compare karta hai.

Changes introduced after a base

git diff A..B

git diff ke context mein A..B ko commit-tree comparison ke perspective se samjho. Ye git log A..B ke meaning se automatically identical nahi hai.

Beginner tip: Initially git diff A B aur git diff HEAD~1 HEAD ko master karo. Range notation baad mein deeply practice karo.

19. Whitespace Ignore Karna

Kabhi-kabhi actual code logic change nahi hua hota, sirf indentation/whitespace change hua hota hai.

git diff -w

Ya:

git diff --ignore-space-at-eol
Caution: Whitespace ignore options review ke liye useful hain, but actual formatting changes accidentally hide bhi ho sakte hain. Critical code review mein normal diff bhi check karo.

30. Advanced — Comparing a File with Another Commit

git diff HEAD~1 -- README.md

Iska meaning: current HEAD se previous commit context ke comparison mein README.md ka difference inspect karna.

Specific commit ke file version ko compare:

git diff COMMIT1 COMMIT2 -- path/to/file

-- separator Git ko clearly batata hai ki iske baad pathspec/file paths hain.

31. Advanced — Diff Between Branches

git diff main feature/login

Do branch tips ke resulting tree differences compare kiye ja sakte hain.

Specific files:

git diff main feature/login -- src/
Important: Branch diff ko “commits ki list” mat samjho. git diff primarily content/tree difference compare karta hai. Commit history dekhne ke liye git log better tool hai.

32. Advanced — Remote Branch ke Saath Diff

Remote branch ke latest state ke against comparison se pehle remote references update karna useful hai:

git fetch origin

Then:

git diff HEAD origin/main

Ya branches ke context mein:

git diff main origin/main
Concept: git fetch remote information update karta hai without automatically merging it into your current branch. Uske baad diff se local vs remote state inspect kar sakte ho.

33. Binary Files ka Diff

Text files ke unlike binary files—jaise kuch images, compiled files, archives—ka normal line-by-line diff meaningful nahi hota.

Git binary files ke liye usually textual patch ke bajay binary change information show karta hai.

Remember: git diff ka strongest use text-based source/config/documentation changes ke inspection mein hota hai.

34. Diff Exit Status / Automation Concept

Automation scripts mein diff ka exit status bhi useful ho sakta hai. Exact behavior command/options ke according interpret karna chahiye.

Example concept:

git diff --quiet
echo $?

Iska use scripts mein “difference exists or not” check karne ke liye kiya ja sakta hai.

35. Common Mistakes

  • git diff mein kuch nahi dikh raha: Changes already staged ho sakte hain. git diff --staged try karo.
  • Staged changes nahi dikh rahe: git diff ke bajay git diff --staged use karo.
  • Commit ke baad diff empty: Current working tree clean ho sakta hai.
  • Wrong branch compare: Branch names verify karo.
  • Whitespace noise: -w useful ho sakta hai, but normal diff bhi inspect karo.
  • Large diff: --stat, --name-only se overview lo.
  • Diff ko history samajhna: History ke liye git log use karo.
  • Diff ko restore command samajhna: git diff changes ko modify nahi karta; primarily comparison/read operation hai.

36. git diff Safe Hai?

Normally yes: git diff ek inspection/comparison command hai. Ye aapke files ko automatically modify, commit, stage ya push nahi karta.

Contrast:

CommandMain action
git diffCompare / inspect
git addStage
git commitCommit
git restoreRestore/discard selected changes
git resetMove/reset refs and/or staging state depending on mode
git revertNew commit se previous change reverse

37. Git Diff vs Git Restore

Ye distinction beginner ke liye important hai.

git diff
→
Dekho kya change hua
git restore
→
Selected changes restore/discard karo

Example:

git diff
git restore app.js
Caution: git restore actual local changes discard kar sakta hai. Isliye pehle git diff se changes inspect karna useful habit hai.

41. Interview Questions

  1. git diff kya karta hai?
    Git states, files ya commits ke beech content differences show karta hai.
  2. git diff aur git status mein difference?
    status repository state/files ka overview deta hai; diff actual content changes show karta hai.
  3. git diff aur git diff --staged mein difference?
    Normal diff unstaged working-tree changes vs index compare karta hai; staged diff index vs HEAD compare karta hai.
  4. git diff HEAD kya karta hai?
    Working tree ke content ko current HEAD ke against compare karta hai.
  5. git diff --cached kya hai?
    Staged changes ko HEAD ke against inspect karta hai.
  6. + aur - ka meaning?
  7. Hunk kya hai?
    Diff output ka localized block of changes with context.
  8. Do commits compare kaise karoge?
    git diff COMMIT1 COMMIT2.
  9. Only changed file names?
    git diff --name-only.
  10. Summary statistics?
    git diff --stat.
  11. Whitespace issues check?
    git diff --check.
  12. git diff kya files ko change karta hai?
    Normally nahi; ye comparison/inspection command hai.
  13. Code review mein git diff kyun important hai?
    Exact additions, deletions aur modifications inspect karne ke liye.
  14. DevOps mein diff ka use?
    Code, Dockerfile, Kubernetes YAML, Terraform, CI/CD configuration aur documentation changes review karne ke liye.

42. Interview Scenario

Question: “Aapne git add . kar diya hai aur ab aap dekhna chahte ho ki commit mein exactly kya jayega. Kya command use karoge?”
