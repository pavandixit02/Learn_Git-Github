1. Pull Request kya hota hai?

Pull Request (PR) GitHub par ek request/proposal hota hai jisme developer apni branch ke changes ko kisi target branch me integrate karne ke liye submit karta hai.

feature/login
→
Pull Request
→

Simple meaning: “Maine apna feature complete kiya hai. Please mere changes ko check karo aur suitable hone par target branch me merge karo.”

2. PR aur Git Pull ka difference

ConceptMeaning
Pull RequestGitHub collaboration/review workflow for proposed changes.
git pullLocal Git command jo remote changes fetch karke current branch me integrate karta hai.
Important: “Pull Request” aur git pull same concept nahi hain.

3. Pull Request create karne se pehle kya hona chahiye?

1️⃣ Repository

Aapke paas target GitHub repository ka access ya fork hona chahiye.

2️⃣ Branch

Feature/fix ke liye separate branch use karo.

3️⃣ Changes

Required code/documentation changes complete karo.

4️⃣ Commit

Meaningful commits banao.

5️⃣ Push

Branch ko GitHub par push karo.

6️⃣ Validation

Tests, lint, build ya relevant checks locally run karo.

Recommended pre-PR commands

git branch --show-current

git diff --staged
git log --oneline --decorate -5

5. How to Create Pull Request — Complete Process

Step 1 — Main branch update karo

git switch main
git pull --ff-only

Isse local main ko remote main ke latest state ke saath update karne me help milti hai.

Step 2 — Feature branch create karo

git switch -c feature/login

Verify:

git branch
git branch --show-current

Step 3 — Code changes karo

Example:

# Edit files
src/login.html
src/login.css
src/login.js

Step 4 — Changes inspect karo

git status
git diff

Step 5 — Changes stage karo

git add .

Ya specific files:

git add src/login.html src/login.css src/login.js

Step 6 — Commit banao

git commit -m "Add user login form"

Step 7 — Branch GitHub par push karo

git push -u origin feature/login
Ab aapki feature branch GitHub par available hai. Ab GitHub UI se Pull Request create kar sakte ho.

Step 8 — GitHub repository open karo

Browser me apni GitHub repository open karo. Push ke baad GitHub often feature branch ke liye Pull Request create karne ka prompt/banner show kar sakta hai.

Step 9 — “Compare & pull request” / Pull Request creation flow open karo

GitHub aapko source branch aur target branch choose karne ka interface deta hai.

Branch direction carefully check karo:
base / target: jisme changes merge karne hain
compare / source: jahan aapke changes hain

Step 10 — Base aur Compare branch select karo

base:    main
compare: feature/login

Typical flow:

feature/login
source / compare
→
main
target / base

Step 11 — PR title likho

Clear title example:

Add user login form with validation

Step 12 — PR description likho

## What
Added a user login form.

## Changes
- Added email field
- Added password field
- Added client-side validation
- Added error messages

## Testing
- Tested valid credentials
- Tested invalid email
- Tested empty fields

## Related Issue
Closes #25

Step 13 — Reviewers / labels / project details

Project configuration ke according reviewers, labels, milestones, projects, assignees etc. add kiye ja sakte hain.

Step 14 — Create Pull Request

Details verify karke Create pull request select karo.

PR created! Ab review, CI checks aur discussion ka phase start hota hai.

7. Pull Request Review kaise hota hai?

PR create hone ke baad reviewer changed files aur discussion ko inspect karta hai.

Reviewer ko kya check karna chahiye?

Correctness

Kya requested functionality correct hai?

Readability

Code understandable hai?

Security

Secrets, auth, validation ya injection risks?

Testing

Relevant tests present/pass hain?

Performance

Unnecessary expensive operations?

Architecture

Existing design ke saath fit?

Review outcomes

OutcomeMeaning
ApproveReviewer changes ko project policy ke according acceptable samajhta hai.
Request changesAuthor ko modifications karne hain before approval/merge.
CommentFeedback/discussion without necessarily changing approval state.

9. CI Checks ka Role

Repository me GitHub Actions ya other CI system configured ho sakta hai jo PR par automatically checks run kare.

🧪 Tests

Unit/integration tests.

🔍 Lint

Code style/quality checks.

🏗️ Build

Application successfully build ho rahi hai ya nahi.

🔐 Security

Dependency/code/security checks.

Agar repository me required checks configured hain aur koi check fail hai, merge allowed na ho sakta hai. Exact behavior branch protection/rules par depend karta hai.

10. How to Merge Pull Request — Complete Process

Step 1 — PR open karo

GitHub repository ke Pull Requests section me jao aur required PR open karo.

Step 2 — Conversation read karo

Reviewer comments, author responses aur resolved/unresolved discussions check karo.

Step 3 — Changed files / diff inspect karo

PR ke Files changed section me actual code changes inspect karo.

Step 4 — CI checks verify karo

Tests, build, lint, security aur repository ke required checks pass hain ya nahi check karo.

Step 5 — Approvals check karo

Agar branch rules required approvals enforce karte hain to required approvals available hone chahiye.

Step 6 — Merge readiness check karo

✅ PR approved

Required review complete.

✅ Checks pass

Required CI checks successful.

✅ No blocking conflict

PR mergeable state me hai.

✅ Requirements satisfied

Project-specific policy complete.

Step 7 — Merge button

GitHub PR page par available merge action se appropriate merge method choose karo.

Step 8 — Merge method choose karo

Repository configuration ke according options available ho sakte hain:

  • Merge commit
  • Squash and merge
  • Rebase and merge

Step 9 — Confirm merge

Selected merge strategy ko review karke merge confirm karo.

Step 10 — Optional branch deletion

PR merge hone ke baad GitHub feature branch delete karne ka option de sakta hai. Short-lived merged branches ko clean up karna common practice hai.

11. Merge Methods in Detail

11.1 Merge Commit

main:    A---B-------M
              \     /
feature:       C---D

Merge commit target branch history me integration point create karta hai.

11.2 Squash and Merge

feature: C---D---E
             \
main:    A----S

Feature branch ke multiple commits ko target branch me single squashed commit ke form me integrate kiya ja sakta hai.

Useful when team clean, compact main-branch history prefer karti hai.

11.3 Rebase and Merge

Before:
main:    A---B
              \
feature:       C---D

After rebase:
main:    A---B---C'---D'

Rebase commits ko target branch ke top par replay karta hai, jisse linear-looking history mil sakti hai. Commit hashes change ho sakte hain.

MethodHistory IdeaTypical Consideration
Merge commitExplicit branch integration pointFull branch topology visible
Squash mergeMultiple PR commits → one target commitClean compact target history
Rebase mergeCommits linear sequence me replayLinear history; rewritten commit hashes
Which one use karna hai? Team repository ki established policy follow karo. Har project ka preferred merge strategy different ho sakta hai.

13. Pull Request me Merge Conflict

Agar source aur target branches ke changes overlap karte hain, GitHub PR ko conflicting state me show kar sakta hai.

Conflict ko locally resolve karna

# Update remote references
git fetch origin

# Switch to feature branch
git switch feature/login

# Bring latest target branch changes
git merge origin/main

# Check conflicts
git status

Conflicted files me markers aa sakte hain:

<<<<<<< HEAD
feature branch version
=======
main branch version
>>>>>>> origin/main

Final correct code manually select/compose karo, markers remove karo, then:

git add <resolved-file>
git commit -m "Resolve merge conflict with main"
git push
Ab GitHub PR updated branch ko re-check karega aur mergeability/CI state update ho sakti hai.

Rebase-based alternative

git fetch origin
git switch feature/login
git rebase origin/main

# Resolve conflict
git add <resolved-file>
git rebase --continue

# If appropriate for your feature branch:
git push --force-with-lease
Shared branches par force push avoid karo. Rebase ke baad force update ki zarurat ho to branch ownership aur team policy verify karo.

14. Pull Request Merge hone ke baad kya karein?

Step 1 — Local main update karo

git switch main
git pull --ff-only

Step 2 — Feature branch clean up

Agar branch merge ho chuki hai aur local branch ki zarurat nahi:

git branch -d feature/login

Remote branch clean up (agar GitHub par ab bhi exist karti ho):

git push origin --delete feature/login
Branch delete karne se pehle confirm karo ki correct branch merge ho chuki hai aur team policy ke according deletion allowed hai.

Step 3 — Continue next task

git switch main
git pull --ff-only
git switch -c feature/next-task

ActionMeaning
MergePR ke proposed changes target branch me integrate karna.
ClosePR ko merge kiye bina close karna.

Important: PR close karna aur PR merge karna completely different actions hain.

16. Draft Pull Request

Agar work abhi complete nahi hai aur aap early feedback chahte ho, GitHub me Draft Pull Request useful ho sakta hai.

Draft PR: “Work in progress hai; abhi final merge ke liye ready nahi.”

Draft ko later “Ready for review” state me convert kiya ja sakta hai.

17. Pull Request Best Practices

  • PR ko focused rakho — unrelated changes avoid karo.
  • Clear title use karo.
  • Description me what/why/testing explain karo.
  • Small aur reviewable commits prefer karo.
  • Tests/build/lint locally run karo.
  • PR open karne se pehle git diff review karo.
  • Target branch ki latest state se aware raho.
  • Review comments ko respectfully handle karo.
  • Secrets commit mat karo.
  • Team ki branch/merge policy follow karo.
  • Large PR ko logical smaller PRs me divide karna consider karo.

22. Common Mistakes

❌ Wrong base/compare branch

PR create karte waqt feature → main ki jagah galti se main → feature select ho sakta hai.

Always check: base = target, compare = source.

❌ PR create karne se pehle changes review na karna

Unwanted files ya debug code PR me chala ja sakta hai.

git status
git diff
git diff --staged

❌ Huge PR

Unrelated features ko ek hi PR me combine karna review ko difficult bana sakta hai.

❌ Failed CI ke baad merge karna

Required checks fail hon to root cause samjho aur project policy follow karo.

❌ Review feedback ignore karna

Reviewer comments ko resolve/discuss karke required changes push karo.

❌ Direct main push

Agar project protected branch/PR workflow use karta hai to direct push allowed nahi ho sakta.

❌ Merge ke baad local main update na karna

git switch main
git pull --ff-only

25. Pull Request Interview Questions

Q1. Pull Request kya hota hai?

GitHub collaboration mechanism jisme source branch ke changes ko target branch me integrate karne ke liye review/proposal create kiya jata hai.

Q2. PR create karne ke basic steps?

Feature branch → changes → commit → push → GitHub → source/target branches select → title/description → Create PR.

Q3. Base aur compare branch kya hoti hain?

Base target branch hoti hai; compare source branch hoti hai jisme proposed changes hain.

Q4. PR merge karne se pehle kya check karna chahiye?

Diff, review comments, required approvals, CI checks, conflicts aur project-specific branch rules.

Q5. Squash merge kya hai?

PR ke multiple commits ko target branch me single squashed commit ke form me integrate karna.

Q6. Merge commit kya hai?

Do histories ko integrate karte waqt explicit merge commit create karne wala merge strategy.

Q7. Rebase and merge kya karta hai?

Source commits ko target branch ke latest base par replay karke linear history-style integration provide kar sakta hai.

Q8. PR me conflict aaye to?

Latest target changes fetch karke source branch ko merge/rebase karo, conflicts resolve karo, commit/push karo aur PR re-check karo.

Q9. Review ke baad PR update kaise hota hai?

Same source branch me requested changes commit karke push karo; existing PR automatically update hota hai.

Q10. PR aur git pull me difference?

PR GitHub review/integration workflow hai; git pull local repository ko remote changes se update karne wala Git command hai.

Q11. Draft PR kab use karenge?

Jab work in progress ho aur early feedback chahiye ho, lekin PR abhi final review/merge ke liye ready na ho.

Q12. Merge ke baad feature branch ka kya?

Project policy ke according merged short-lived branch ko delete kiya ja sakta hai; local main ko latest state se update karna chahiye.
