Git Pull & Fetch

git fetch aur git pull ko beginner se intermediate level tak samajhne ke liye complete theory + practical guide.

1. Git Fetch & Pull Kya Hote Hain?

git fetch aur git pull dono remote repository se latest changes ko local repository tak lane ke liye use hote hain, lekin dono ka behaviour different hai.

Simple Definition:
Fetch = Remote changes ko download/update karo, lekin current working branch me automatically integrate mat karo.

Pull = Remote changes ko fetch karo aur configured/current branch workflow ke according integrate karo.
CommandSimple Meaning
git fetchRemote updates lao, inspect karo, automatically current branch me merge mat karo.
git pullRemote updates lao aur unhe current branch ke saath integrate karne ki koshish karo.

2. Remote Repository Ka Concept

Example maan lo:

Local Repository  ←→  Remote Repository
     Git                  GitHub

Remote ka common naam:

origin

Check karne ke liye:

git remote -v

Typical output:

origin  https://github.com/example/project.git (fetch)
origin  https://github.com/example/project.git (push)

3. Fetch Kaise Work Karta Hai?

Remote Repository→git fetch→Remote-tracking refs update→Inspect

Example:

git fetch origin

Fetch remote se new commits aur references ko local repository me update karta hai. Current checked-out branch ko automatically merge nahi karta.

4. Remote-Tracking Branch Kya Hai?

Fetch ke baad remote branch ki local tracking reference update hoti hai. Example:

origin/main
origin/develop
origin/feature-login

Ye local branch names nahi, balki remote-tracking references hain.

Important: origin/main ka matlab roughly remote origin ki main branch ka locally stored reference hai.

5. Fetch Ke Baad Kya Hota Hai?

Suppose:

Before fetch:

Local main: A --- B
origin/main: A --- B

Remote main: A --- B --- C --- D

Run:

git fetch origin

After fetch:

Local main: A --- B
origin/main: A --- B --- C --- D
Remote main: A --- B --- C --- D

Notice: Local main automatically C/D par move nahi hui. Pehle aap inspect/integrate kar sakte ho.

6. Fetch Commands

All configured remotes

git fetch --all

Specific remote

git fetch origin

Specific branch

git fetch origin main

Prune deleted remote-tracking branches

git fetch --prune

Remote-specific prune:

git fetch origin --prune

7. git fetch --prune Kyu Useful Hai?

Agar remote par koi branch delete ho gayi hai, to uska old remote-tracking reference local repository me reh sakta hai jab tak prune na ho.

git fetch --prune

Ye stale remote-tracking references ko clean karne me help karta hai.

8. Fetch Ke Baad Changes Inspect Kaise Kare?

Fetch ke baad:

git status
git branch -a
git log --oneline --decorate --graph --all

Local main aur remote-tracking main ka difference:

git log main..origin/main --oneline

Detailed code difference:

git diff main..origin/main
Is workflow ka major advantage hai: pehle remote changes dekho, phir decide karo ki merge/rebase kaise karna hai.

9. Git Pull Kaise Work Karta Hai?

Remote Repository→Fetch→Integrate→Current Branch Updated

Basic command:

git pull

Conceptually, git pull pehle remote updates fetch karta hai aur phir configured integration strategy ke through current branch ko update karne ki koshish karta hai.

10. Basic Git Pull

git pull

Agar upstream configured hai, Git current branch ke configured upstream remote/branch se changes la sakta hai.

Explicit form:

git pull origin main

11. Pull = Fetch + Integration

Conceptually:

git pull origin main

ko simple mental model me samjho:

git fetch origin
# then integrate fetched main into current branch

Integration merge ya rebase strategy/configuration ke according ho sakti hai.

Important: Git pull ko blindly “always fetch + merge commit” mat samjho. Pull ki integration behaviour configuration/options par depend kar sakti hai.

12. Git Pull With Rebase

Rebase-based pull explicitly request kar sakte ho:

git pull --rebase

Iska purpose fetched changes ko current local work ke saath rebase workflow ke through integrate karna hota hai.

Concept: Merge aur rebase different history strategies hain. Team workflow ke according correct strategy follow karein.

13. Git Pull --ff-only

git pull --ff-only

Ye pull ko sirf fast-forward situation me allow karta hai. Agar local branch aur remote branch diverge ho gayi hain aur fast-forward possible nahi hai, command stop ho sakti hai.

Useful when you want to avoid Git automatically creating a merge commit during pull.

14. Pull vs Fetch - Main Difference

Featuregit fetchgit pull
Remote data downloadYesYes
Current branch automatically updateNoIntegration attempt
Inspection before integrationEasyLess explicit
Risk of immediate conflictLower, because no automatic integrationPossible during integration
Typical useReview remote changes firstUpdate current working branch

15. Fetch vs Pull Real-Life Analogy

Imagine team ne shared project me changes upload kiye.

FETCH:
“Changes mere paas lao, pehle mujhe dekhne do.”

PULL:
“Changes lao aur meri current branch ke saath integrate karne ki koshish karo.”

16. Practical Example - Fetch First

git status
git fetch origin

git log main..origin/main --oneline
git diff main..origin/main

Agar changes acceptable hain, integration approach choose kar sakte ho:

git merge origin/main

Ya team workflow ke according rebase:

git rebase origin/main

17. Practical Example - Pull

git switch main
git pull origin main

Ye current main branch ko remote origin/main ke latest changes ke saath integrate karne ka common workflow hai.

18. Pull Se Pehle Working Tree Clean Kyu Rakhte Hain?

Pull ke time local uncommitted changes ho sakte hain jo incoming changes se conflict kar sakte hain.

Check:

git status

Agar important local changes hain, to commonly:

  • Commit karo, ya
  • Appropriate stash workflow use karo, ya
  • Changes ko carefully resolve karne ke liye prepare karo.
Uncommitted work ko blindly overwrite ya discard na karein.

19. Pull Conflict Kya Hota Hai?

Agar local aur remote changes same area of code ko incompatible way me modify karte hain, integration conflict aa sakta hai.

Example workflow:

git pull origin main

# conflict appears
git status

# files edit karke conflicts resolve
git add <resolved-file>

# merge-based pull ke case me
git commit

Exact next command Git ki current operation state par depend karti hai. git status ko follow karein.

20. Rebase Pull Conflict

Agar:

git pull --rebase

ke during conflict aaye:

git status

# conflict resolve
git add <resolved-file>
git rebase --continue

Rebase cancel karna ho:

git rebase --abort

21. Merge vs Rebase During Pull

ApproachCommandGeneral Effect
Merge-basedgit pullFetched changes ko merge workflow se integrate kar sakta hai.
Rebase-basedgit pull --rebaseLocal commits ko updated remote base ke upar replay kar sakta hai.
Fast-forward onlygit pull --ff-onlyOnly fast-forward update allow karta hai.

22. Branch Tracking & Upstream

Agar local branch remote branch ko track karti hai, to simple:

git pull

kaafi ho sakta hai.

Tracking information:

git branch -vv

Example concept:

main  abc1234 [origin/main] Update README
origin/main upstream/remote-tracking reference hai; exact tracking state git branch -vv se verify karein.

23. Fetch/Pull With Multiple Remotes

Agar repository me multiple remotes hain:

git remote -v

Specific remote fetch:

git fetch upstream

Specific remote se pull:

git pull upstream main

24. Fetch vs Pull vs Clone

CommandMain Purpose
git cloneRemote repository ki initial local copy create karna.
git fetchRemote updates download/reference karna without automatically integrating into current branch.
git pullRemote updates fetch karke current branch me configured integration apply karna.

25. Useful Fetch Commands

# Fetch default remote
git fetch

# Fetch specific remote
git fetch origin

# Fetch all remotes
git fetch --all

# Prune stale remote-tracking refs
git fetch --prune

# Fetch + prune specific remote
git fetch origin --prune

# Fetch specific branch
git fetch origin main

26. Useful Pull Commands

# Pull configured upstream
git pull

# Pull specific remote branch
git pull origin main

# Pull with rebase
git pull --rebase

# Pull only if fast-forward possible
git pull --ff-only

27. Recommended Safe Inspection Workflow

git status→git fetch→git log/diff→merge/rebase 
git status
git fetch origin

git log main..origin/main --oneline
git diff main..origin/main

# Choose team-approved integration:
git merge origin/main
# OR
git rebase origin/main
Ye workflow especially useful hai jab aap remote changes ko integrate karne se pehle inspect karna chahte ho.

31. Common Mistakes

  1. Fetch aur pull ko same command samajhna.
  2. origin/main ko local main branch samajhna.
  3. Fetch ke baad automatically local branch update ho jayegi sochna.
  4. Uncommitted changes ke saath blindly pull karna.
  5. Conflict me files resolve kiye bina random commands run karna.
  6. git pull --rebase use karke rebase workflow na samajhna.
  7. Remote branch delete hone ke baad stale reference ko clean na karna.

32. Complete Practical Lab

Step 1: Current state

git status
git branch -vv
git remote -v

Step 2: Fetch

git fetch origin

Step 3: Inspect

git log main..origin/main --oneline
git diff main..origin/main

Step 4: Integrate

git merge origin/main

Alternative: Pull

git pull origin main

Alternative: Rebase pull

git pull --rebase origin main
Lab Goal: Fetch se remote changes inspect karna aur pull/merge/rebase se integration workflow samajhna.

33. Interview Questions

Q1. git fetch kya karta hai?

Remote changes ko download karke remote-tracking references update karta hai, current branch ko automatically integrate nahi karta.

Q2. git pull kya karta hai?

Remote changes fetch karke configured integration strategy ke through current branch ko update karne ki koshish karta hai.

Q3. Fetch aur pull me main difference?

Fetch inspection ke liye changes laata hai without current branch integration; pull fetch ke baad integration attempt karta hai.

Q4. origin/main kya hai?

Remote origin ki main branch ka local remote-tracking reference.

Q5. git fetch --prune kya karta hai?

Stale remote-tracking references ko remove/clean karne me help karta hai.

Q6. git pull --rebase kya karta hai?

Fetch ke baad changes ko rebase workflow ke through current local work ke saath integrate karta hai.

Q7. git pull --ff-only kyu use karte hain?

Sirf fast-forward update allow karne ke liye; divergence par command stop ho sakti hai.

Q8. Pull conflict aaye to pehla useful command?

git status, jisse current operation aur conflicted files ka state samajh sakte hain.
