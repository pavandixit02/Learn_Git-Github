8. MOST IMPORTANT — Vite base Configuration

GitHub Pages par Vite React deployment ka sabse important concept base path hai.

Problem Kya Hoti Hai?

Suppose repository ka naam:

my-react-app

Project Pages URL conceptually:

https://YOUR-USERNAME.github.io/my-react-app/

Agar Vite assets ko root se reference kare:

/assets/index.js

to browser wrong location par asset search kar sakta hai, because project website root actually /my-react-app/ ke andar hai.

Solution: vite.config.js

import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  base: '/my-react-app/',
})
Rule: Agar project GitHub Pages par repository subpath ke under host ho raha hai, to Vite ka base repository path ke according configure karna important hota hai.

Username Pages Site vs Project Pages

Project Pageshttps://USERNAME.github.io/REPO/Usually /REPO/

11. Method A — GitHub Actions (CI/CD) Deployment

Ye approach source repository mein workflow file rakhti hai jo push ke baad build aur Pages deployment automate kar sakti hai.

High-Level Flow

git push
→
GitHub Actions
→
npm ci
→
npm run build
→
dist/
→
GitHub Pages

Workflow File

File path:

.github/workflows/deploy.yml

Example workflow:

name: Deploy Vite React App to GitHub Pages

on:
  push:
    branches: ["main"]

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Build
        run: npm run build

      - name: Setup Pages
        uses: actions/configure-pages@v5

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./dist

      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
Important: Workflow versions and GitHub Pages configuration can evolve. Workflow ko use karte waqt repository ke current Pages settings aur GitHub Actions documentation ke according verify karna good practice hai.

Pages Settings

Repository ke Pages settings mein GitHub Actions based deployment source select/configure karna hota hai when using the Actions deployment model.

16. React Router & GitHub Pages — Important SPA Concept

Vite React apps often SPA (Single Page Application) hoti hain. React Router client-side URL handling provide kar sakta hai.

Problem

Suppose app mein route hai:

/about
/projects
/contact

Client-side navigation se route work kar sakta hai, lekin user directly GitHub Pages par /about open kare to hosting ko actual server file/path request mil sakti hai. SPA hosting mein fallback behavior important ho jata hai.

HashRouter Option

import { HashRouter } from "react-router-dom"


  <App />

URL concept:

https://USERNAME.github.io/REPO/#/about

Hash-based routing static hosting ke saath simple option ho sakta hai because hash browser-side handle hota hai.

BrowserRouter

BrowserRouter cleaner URLs provide kar sakta hai, but static hosting par direct deep-link requests ke liye appropriate fallback/rewrite strategy chahiye. GitHub Pages ke context mein deployment-specific SPA workaround/configuration required ho sakti hai.

Interview point: “React Router route works by clicking, but refreshing /about gives 404” is a classic SPA static-hosting deployment issue.

17. Environment Variables in Vite

Vite environment variables ko import.meta.env ke through expose karta hai. Client-side exposed values secret nahi maani ja sakti.

Example

VITE_API_URL=https://api.example.com

React code:

const apiUrl = import.meta.env.VITE_API_URL;
Critical: VITE_ prefixed values frontend bundle mein available ho sakti hain. API secret, private key, password ya token ko frontend environment variable mein secret samajhkar store mat karo.

Environment Files

.env
.env.local
.env.production

Project requirements ke according sensitive local values ko Git se ignore karna aur public configuration ko carefully manage karna important hai.

18. Asset Paths — Public vs src/assets

src/assets

Imported assets Vite build pipeline ke through process ho sakte hain.

import logo from "./assets/logo.png"

<img src={logo} alt="Logo" />

public

Public directory ke assets direct public paths ke through reference kiye ja sakte hain, depending on Vite configuration.

<img src="/logo.png" alt="Logo" />
GitHub Pages note: Project Pages subpath ke saath absolute root paths carefully use karo. Vite base configuration aur asset reference strategy ko together samjho.

20. Common Errors & Troubleshooting

Error 1 — Blank White Page

  • Browser Console open karo.
  • JS asset path check karo.
  • base configuration verify karo.
  • Network tab mein 404 assets check karo.

Error 2 — CSS/JS 404

Project Pages mein base: '/REPO/' missing/wrong ho sakta hai.

export default defineConfig({
  base: '/REPO/',
})

Error 3 — GitHub Pages URL par 404

  • Pages enabled?
  • Correct deployment source?
  • Actions workflow successful?
  • Repository path correct?
  • Published deployment available?

Error 4 — React Router Refresh 404

SPA fallback/routing strategy check karo. HashRouter simple static-hosting option ho sakta hai.

Error 5 — Environment Variable Undefined

  • Name VITE_ prefix se start?
  • Correct environment file?
  • Build ke time variable available?
  • Change ke baad fresh build kiya?

Error 6 — npm install / npm ci Problem

node -v
npm -v
npm ci

Lockfile aur Node/npm compatibility verify karo.

Error 7 — Workflow Failed

GitHub → Actions → failed workflow → failed step ka log read karo. Failure ko blindly rerun karne ke bajay actual step identify karo.

23. Security Concepts

  • Public repository mein secrets commit mat karo.
  • Frontend JavaScript mein private API key ko secret mat samjho.
  • GitHub Actions permissions ko minimum required access tak rakho.
  • Third-party GitHub Actions ko use karne se pehle source/trust review karo.
  • Dependencies ko regularly update aur audit karo.
  • Production site par sensitive data accidentally expose na ho, verify karo.

28. Interview Questions

  1. Vite kya hai? Modern frontend development/build tool that provides a fast dev server and production build pipeline.
  2. React aur Vite mein difference? React UI library hai; Vite development/build tooling provide karta hai.
  3. npm run dev vs npm run build? Dev server vs production build.
  4. dist folder kya hai? Production build output.
  5. GitHub Pages par Vite app mein base path important kyun? Project Pages repository subpath ke under host hota hai, isliye generated asset URLs ko correct public path chahiye.
  6. Vite mein base kaise set karte ho? vite.config.js mein base: '/REPO/'.
  7. GitHub Actions kya karta hai? Automated workflow ke through build/test/deploy tasks run kar sakta hai.
  8. gh-pages package ka role? Generated static output ko GitHub Pages publishing branch/source tak publish karne mein help karta hai.
  9. dist ko Git mein commit karna zaroori hai? Deployment strategy par depend karta hai; Actions build workflow mein normally source repository mein dist commit karna unnecessary hai.
  10. React Router refresh par 404 kyun? SPA client-side routing aur static hosting ke server-side path handling ke difference ki wajah se.
  11. VITE_ variables secret kyun nahi? Client bundle mein expose ho sakti hain.
  12. GitHub Pages backend server kyun nahi hai? It is designed for static site publishing, not a persistent application backend runtime.
  13. CI/CD flow kya hoga? Push → install → build → artifact → deploy → validate.

29. Common Mistakes

  • base set na karna ya wrong repository name dena.
  • npm run build locally test na karna.
  • dist/ aur source code ka role confuse karna.
  • Wrong Pages source select karna.
  • GitHub Actions permissions/configuration ignore karna.
  • React Router deep links test na karna.
  • Frontend environment variables mein secrets rakhna.
  • Asset paths mein leading slash ka impact ignore karna.
  • Filename case mismatch ignore karna.
  • Workflow logs read kiye bina random fixes karna.
