🔄 Git Revert Command

Complete Study Material | Beginner → Intermediate

📌 1. What is Git Revert?

git revert is a Git command used to safely undo the changes introduced by a previous commit.

Instead of deleting or changing the existing commit history, git revert creates a new commit that reverses the changes made by the selected commit.

In simple words:

Git Revert = Previous commit ke changes ko reverse karna without deleting the original commit from history.

🎯 2. Why Do We Use Git Revert?

Suppose you have a project and you made a commit that introduced a bug. The commit has already been pushed to GitHub and other developers may already have it.

In this situation, deleting or rewriting history can create problems for other developers.

git revert allows us to undo the changes while keeping the original commit history intact.

Common Uses:

  • Undo a bad commit.
  • Remove a buggy feature.
  • Reverse a production change.
  • Safely undo changes on a shared branch.
  • Keep Git history clean and traceable.

📖 3. Definition

Definition:

Git revert is a command that creates a new commit which reverses the changes introduced by an earlier commit, without removing the original commit from the repository history.

⚙️ 4. How Does Git Revert Work?

Consider the following commit history:

``` 
A ---- B ---- C ---- D
              ↑
          Bad Commit
```

Suppose commit C introduced a bug.

We execute:

``` 
git revert C
```

Git does NOT delete commit C.

Instead, Git creates a new commit that reverses the changes introduced by C.

``` 
A ---- B ---- C ---- D ---- E
              ↑           ↑
           Bad Commit   Revert Commit
```

Here, E is the new revert commit.

🧠 5. Important Concept: Revert Does NOT Delete History

This is the most important concept to understand.

When you run:

``` 
git revert <commit-id>
```

Git keeps the original commit.

Git simply creates another commit that performs the opposite changes.

Example:

``` 
Original History:

A → B → C


After Revert:

A → B → C → D

C = Original commit
D = Revert commit
```

💻 6. Basic Syntax

``` 
git revert <commit-id>
```

Example:

``` 
git revert a1b2c3d
```

Here:

  • a1b2c3d = commit ID
  • Git creates a new commit that reverses that commit's changes.

🔍 7. How to Find Commit ID?

Before reverting a commit, we usually need its commit ID.

Use:

``` 
git log
```

Example output:

``` 
commit 7a8b9c0
Author: Pavan
Message: Added contact form

commit 4d5e6f7
Author: Pavan
Message: Added navigation

commit 1a2b3c4
Author: Pavan
Message: Initial website
```

Suppose the contact form introduced a problem.

We can revert:

``` 
git revert 7a8b9c0
```

⬅️ 8. git revert HEAD

HEAD represents the current commit you are pointing to.

To revert the latest commit:

``` 
git revert HEAD
```

Git will create a new commit that reverses the changes introduced by the latest commit.

Example:

``` 
A → B → C
        ↑
       HEAD
```

After:

``` 
git revert HEAD
```

History becomes:

``` 
A → B → C → D
        ↑   ↑
      Original
              Revert
```

🎯 9. Revert a Specific Commit

Suppose your history is:

``` 
A → B → C → D → E
```

You discover that commit C introduced a bug.

You can run:

``` 
git revert C
```

The resulting history will look conceptually like:

``` 
A → B → C → D → E → R
         ↑          ↑
      Bad Commit   Revert
```

Notice that C is still present.

📝 10. Revert Commit Message

When you run:

``` 
git revert <commit-id>
```

Git normally opens your configured text editor so you can confirm or modify the revert commit message.

A typical message may look like:

``` 
Revert "Added contact form"

This reverts commit 7a8b9c0.
```

Save and close the editor to complete the revert.

⚡ 11. git revert --no-edit

If you want Git to use the default revert commit message without opening the editor:

``` 
git revert --no-edit <commit-id>
```

Example:

``` 
git revert --no-edit a1b2c3d
```

🧪 12. Practical Example

Step 1: Create a file

``` 
index.html
```

Step 2: Add the file

``` 
git add index.html
```

Step 3: Commit

``` 
git commit -m "Add website"
```

Step 4: Make another change

Suppose you add a feature that breaks the website.

Step 5: Commit the change

``` 
git add .
git commit -m "Add broken feature"
```

Step 6: Find the commit

``` 
git log --oneline
```

Step 7: Revert the bad commit

``` 
git revert <bad-commit-id>
```

Step 8: Check history

``` 
git log --oneline
```

You will see the original commit and a new revert commit.

🌐 13. Git Revert with GitHub

Git revert is especially useful when working with a shared GitHub repository.

Example workflow:

``` 
Developer
    ↓
git add .
    ↓
git commit
    ↓
git push
    ↓
GitHub
    ↓
Bug discovered
    ↓
git revert
    ↓
git push
```

The revert commit can then be pushed to GitHub like any normal commit.

``` 
git push origin main
```

👥 14. Why Revert is Good for Shared Branches?

Imagine multiple developers are working on the same main branch.

If you rewrite history using commands such as git reset and force push, other developers may experience synchronization problems.

Revert is usually safer because it adds a new commit instead of rewriting existing public history.

⚠️ 15. What if Git Revert Causes a Conflict?

Sometimes the changes made after the target commit make it impossible for Git to automatically reverse the original change.

In that case, Git reports a conflict.

Check the conflict:

``` 
git status
```

Manually resolve the conflicted files.

Then stage the resolved files:

``` 
git add .
```

Finally continue the revert:

``` 
git revert --continue
```

If you decide that you don't want to continue:

``` 
git revert --abort
```

🔢 16. Reverting Multiple Commits

Multiple commits can be reverted, but you should understand the order and dependencies between those commits.

For example:

``` 
A → B → C → D → E
```

You may need to reverse changes introduced by more than one commit.

Git supports reverting multiple commits by specifying multiple commits or by using an appropriate range/workflow.

Always inspect the history first:

``` 
git log --oneline
```

🔀 17. Reverting a Merge Commit

Reverting a merge commit is more advanced because a merge commit has multiple parents.

Git needs to know which parent should be considered the mainline.

The general syntax is:

``` 
git revert -m <parent-number> <merge-commit>
```

Example:

``` 
git revert -m 1 abc1234
```

The -m option specifies the mainline parent.

This should be used carefully, especially on important shared branches.

🆚 18. Git Revert vs Git Reset vs Git Restore

Command Main Purpose Changes History? Typical Use
git restore Restore file changes No commit history rewrite Discard working-tree changes
git revert Undo a commit No, adds a new commit Safely undo shared/public commits
git reset Move branch/HEAD to another point Can rewrite history Local/private history cleanup

🧠 19. Revert vs Reset Example

Git Revert

``` 
A → B → C

git revert C

A → B → C → D
            ↑
       Revert Commit
```

Original commit C remains in history.

Git Reset

``` 
A → B → C

git reset --hard B

A → B
```

The branch pointer moves backward to B. Depending on the reset mode and whether the commits are shared, this can rewrite history.

🏠 20. Real-Life Analogy

Imagine you wrote a document and submitted it.

Later you discover that one section is wrong.

Instead of deleting your original submission, you create a new correction document saying:

"The previous change should be reversed."

This is similar to how git revert works.

The original commit remains available for history, while a new commit reverses its effect.

📚 21. Important Git Revert Commands

``` 
# Revert a specific commit
git revert <commit-id>

# Revert latest commit
git revert HEAD

# Revert without opening editor
git revert --no-edit <commit-id>

# Check status during conflict
git status

# Continue a conflicted revert
git revert --continue

# Cancel a conflicted revert
git revert --abort

# Revert a merge commit
git revert -m 1 <merge-commit-id>

# Push revert commit to GitHub
git push origin main
```

✅ 22. Best Practices

  • Always check the commit history before reverting.
  • Use git log --oneline to quickly identify commits.
  • Use revert for commits that are already shared with others.
  • Understand the changes being reversed before executing the command.
  • Check git status if a conflict occurs.
  • Test your project after the revert.
  • Push the revert commit only after verifying the result.

❌ 23. Common Mistakes

  1. Thinking that git revert deletes the original commit.
  2. Confusing git revert with git reset.
  3. Reverting the wrong commit.
  4. Not checking git log before reverting.
  5. Ignoring merge conflicts.
  6. Forgetting to test the application after reverting.

🏆 26. Final Concept

The easiest way to remember git revert is:

"Commit ko delete nahi karna hai, bas uske changes ko reverse karna hai."

Git keeps the original commit and creates a new commit that reverses its changes.

``` 
Original:

A → B → C


After:

A → B → C → D
         ↑   ↑
       Original
               Revert
```

Therefore:

Git Revert = Safe way to undo a committed change by creating another commit.
