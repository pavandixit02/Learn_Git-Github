Git Branch

Beginner se intermediate level tak complete theory + practical guide.

1. Git Branch Kya Hota Hai?

Git Branch repository me development ki separate line/reference hoti hai. Isse feature, bug fix, experiment ya alag work ko main codebase se isolate karke develop kar sakte hain.

Simple Definition:
Branch ek movable reference hai jo commits ki ek development line ko point karta hai.
A --- B --- C  ← main
             \
              D --- E  ← feature-login

2. Branch Kyu Use Karte Hain?

  • Features ko isolate karna
  • Bug fixes separate rakhna
  • Parallel development
  • Experimental changes
  • Stable main branch maintain karna
  • Pull Request/code review workflow

3. Real-Life Analogy

Main project ko ek main road samjho. Developer feature ke liye side road (branch) leta hai, kaam complete karta hai, review ke baad changes main road me merge hote hain.

main→feature branch→code→review→merge

4. Branch Internally Kaise Work Karti Hai?

Git me branch ek movable pointer/reference hoti hai jo kisi commit ko point karti hai.

A --- B --- C ← main
↑
HEAD

Feature par commit hone par feature pointer aage move hota hai; main apni jagah reh sakti hai.

5. HEAD Kya Hota Hai?

HEAD current checkout context ko identify karta hai. Usually HEAD current branch ko point karta hai.

git status
git branch --show-current
Branch aur HEAD same nahi hain: branch ek reference hai, HEAD current checkout context ka reference hai.

6. Branch Check Karna

Local branches

git branch

Current branch

git branch --show-current
git status

Remote branches

git branch -r

All branches

git branch -a

7. New Branch Create Karna

git branch feature-login

Ye branch create karta hai, automatically switch nahi karta.

Remember: git branch name = create only.

8. Create + Switch Ek Saath

Modern

git switch -c feature-login

Traditional

git checkout -b feature-login

9. Existing Branch Par Switch

git switch main

Traditional:

git checkout main

10. Branch Rename

# Current branch
git branch -m new-name

# Specific branch
git branch -m old-name new-name

11. Local Branch Delete

git branch -d feature-login

-d safer delete hai.

git branch -D feature-login
-D force delete hai; unmerged work lose ho sakta hai.

12. Remote Branch Delete

git push origin --delete feature-login

Local branch alag se delete ki ja sakti hai.

13. Branch Remote Par Push

git push -u origin feature-login

-u upstream tracking set karta hai. Baad me commonly:

git push
git pull

14. Remote Branch Se Local Branch

git fetch origin
git switch -c feature-login --track origin/feature-login

Traditional:

git checkout -b feature-login origin/feature-login

15. Branch Tracking

Local branch kisi remote-tracking branch ko upstream ke roop me track kar sakti hai.

git branch -vv
feature-login → origin/feature-login

16. Branch Compare

git diff main..feature-login
git log main..feature-login --oneline
git log --oneline --graph --all --decorate

17. Branch Merge

git switch main
git merge feature-login
main: A --- B -------- M
\ /
feature: C -- D

Merge branch ke changes ko target branch me integrate karta hai.

18. Fast-Forward vs Merge Commit

Fast-Forward

A --- B --- C ← feature
          ↑
         main

Merge me main pointer C par move ho sakta hai.

Merge Commit

A --- B --- C --- M ← main
     \       /
      D --- E

19. Merge Conflict

git switch main
git merge feature-login
# conflict resolve karein
git status
git add .
git commit

Conflict ke time git status se current state check karna important hai.

20. Rebase Basic Concept

git switch feature-login
git rebase main

Rebase feature commits ko updated base ke upar replay karta hai.

Rebase history rewrite kar sakta hai. Already-shared commits par carefully use karein.

21. Complete Practical Workflow

git switch main
git pull
git switch -c feature-login

# code changes
git status
git add .
git commit -m "Add login feature"
git push -u origin feature-login

# GitHub/GitLab: Pull Request → Review → Merge
Ye common branch-based collaborative workflow hai.

24. Branch vs Commit vs HEAD

ConceptMeaning
CommitSaved snapshot/history point.
BranchMovable reference to a commit line.
HEADCurrent checkout context reference.
origin/mainRemote-tracking reference.

25. Common Mistakes

  1. git branch new ke baad automatically switch hone ki expectation.
  2. Current branch check kiye bina commit karna.
  3. git branch -D se unmerged work delete karna.
  4. Local aur remote branch ko same samajhna.
  5. Upstream tracking na samajhna.
  6. Shared branch par careless rebase/reset/force push karna.
  7. Merge conflict resolve ke baad status verify na karna.

27. Interview Questions

Q1. Git branch kya hai?

Separate development line/reference jo parallel work allow karti hai.

Q2. git branch feature?

Branch create karta hai, switch nahi.

Q3. Create + switch?

git switch -c feature ya git checkout -b feature.

Q4. Current branch?

git branch --show-current ya git status.

Q5. -d vs -D?

-d safer delete; -D force delete.

Q6. -u ka use?

Upstream tracking set karna.

Q7. Merge?

Ek branch ke changes ko doosri branch me integrate karna.

Q8. Rebase?

Commits ko new base par replay karna; history rewrite ho sakti hai.

28. Quick Revision

CREATE → SWITCH → CODE → ADD → COMMIT → PUSH → PR → REVIEW → MERGE
One-line revision:
Git Branch code ko separate development lines me organize karta hai, parallel work enable karta hai aur controlled merge/review workflow support karta hai.
