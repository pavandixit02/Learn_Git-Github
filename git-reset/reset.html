Git Reset

HEAD, staging area aur working tree ko samajhne ke saath reset ke soft, mixed aur hard modes ka guide.

1. Git Reset Kya Hota Hai?

git reset current branch ke HEAD ko kisi specified commit par move kar sakta hai aur mode ke according staging area aur working tree ko bhi change kar sakta hai.

Simple Definition:
Reset = Branch/HEAD ko pichhli commit state par move karna, with optional index/worktree changes.
Important: Reset especially --hard ke saath destructive ho sakta hai. Shared branch par use karne se pehle bahut carefully sochna chahiye.

2. Reset Ke 3 Important Modes

ModeHEADStagingWorking Tree
--softMoveChanges staged rehte hainUnchanged
--mixed (default)MoveReset/unstagedUnchanged
--hardMoveResetChanges discard ho sakte hain

3. Soft Reset

git reset --soft HEAD~1

Last commit remove from current branch position ho jayega, lekin us commit ke changes staging area me available rahenge.

Useful when: commit ko undo karke changes ko dobara edit/recommit karna ho.

4. Mixed Reset

git reset --mixed HEAD~1

Ye default mode hai:

git reset HEAD~1

HEAD pichhe move hota hai aur changes staging area se unstage ho jate hain, lekin working files ke changes generally remain karte hain.

Remember: Mixed reset = commit undo + changes unstaged.

5. Hard Reset

git reset --hard HEAD~1

HEAD, staging area aur working tree ko target commit ki state ke saath align karta hai.

Danger: Uncommitted changes lose ho sakte hain. Is command ko blindly use na karein.

6. Real Example

A --- B --- C
          ↑
         HEAD

Agar:

git reset --soft B

to branch pointer B par aa jayega, aur C ke changes staged state me available rahenge.

Hard reset:

git reset --hard B

to working tree bhi B ke according reset ho sakta hai.

7. Reset Ka Working Flow

Current HEAD→git reset→Target Commit→HEAD / Index / Working Tree Adjust

8. Reset Kab Use Kare?

  • Local branch par last commit undo karna.
  • Commit ko modify/rewrite karna.
  • Changes ko staged/unstaged state me adjust karna.
  • Local history ko clean karna.
Agar commits already shared/pushed hain, reset se pehle team impact samjhein. Public history rewrite problems create kar sakta hai.

9. Reset vs Revert

FeatureResetRevert
New commitNoYes
HEAD moveYesNo, current branch history remains
History rewriteCan rewrite local branch historyNo

Working tree controlSoft/mixed/hard modesCreates inverse changes

10. Common Mistakes

  • git reset --hard ko casually run karna.
  • Reset aur revert ko same samajhna.
  • Already-pushed shared commits par reset kar dena.
  • Reset se pehle git status aur git log --oneline check na karna.

11. Interview Questions

Q1. git reset ke main modes?

--soft, --mixed (default), aur --hard.

Q2. Soft reset kya karta hai?

HEAD move karta hai aur changes staged rehte hain.

Q3. Mixed reset kya karta hai?

HEAD move karta hai, changes unstage karta hai, working tree generally preserve karta hai.

Q4. Hard reset risky kyu hai?

Target commit ke bahar ke uncommitted working-tree changes discard ho sakte hain.
